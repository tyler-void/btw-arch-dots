# Forgejo on msi-server

Personal git forge for **tyler** at **https://git.tyler-void.dev**. Set up 2026-10-17.

| | |
|---|---|
| Version | Forgejo 15 LTS (`codeberg.org/forgejo/forgejo:15`, 15.0.10 at setup), SQLite |
| Web + HTTPS git | `https://git.tyler-void.dev` → Cloudflare Tunnel `msi-server-forgejo` (`db8f8f61-e2cf-483c-b944-12fae5e03dc6`) → `http://forgejo:3000` |
| SSH git | `ssh://git@msi-server.tail2571f1.ts.net:2222/tyler/<repo>.git`, **Tailscale only** (bound to 100.69.193.44) |
| Host ports | only `100.69.193.44:2222`. No HTTP port is published; the web is reachable only through the tunnel |
| Accounts | registration disabled, OpenID off, no mail. Public repos readable without login |
| Backups | `forgejo dump` nightly at 03:30 → `dumps/`, 14 days kept |
| Theme | Enhalation (Mocha), the default for visitors. Generated by btw-arch-dots `scripts/gen-theme.py` |
| Source of truth | btw-arch-dots `servers/msi-server/forgejo/` (deploy: see the end of this file). The guide is `docs/forgejo.md` |

Other services share this box (Portainer, CI runners, a friend's services). They are not part of this stack. Don't touch them from here.

## Git usage

- Clone public repos over HTTPS from anywhere: `git clone https://git.tyler-void.dev/tyler/<repo>.git`
- Push over SSH, on the tailnet: `git remote add origin ssh://git@msi-server.tail2571f1.ts.net:2222/tyler/<repo>.git`
- **Anything large (pushes, API uploads): use the tailnet, not the public URL.** Uploads *into* the
  server through the tunnel crawl at ~0.1–1 Mbit/s on this ISP. Cloudflare also cuts requests at
  100 s (524) and rejects bodies over about 100 MB (413). Downloads through the tunnel are fine. The
  measurements are in `docs/forgejo.md` (Upload performance).
- If HTTPS git ever starts getting HTML challenge pages instead of git data, a Cloudflare security
  feature (Bot Fight Mode / a challenge rule) is catching git clients. Add a WAF skip rule for
  `git.tyler-void.dev` rather than turning protection off for the whole zone.

## Backups

The nightly job runs `forgejo dump` inside the container. One zip holds every repo (`repos/`), the database
as SQL (`forgejo-db.sql`), the config with its secrets (`app.ini`), and attachments, avatars and other data (`data/`).

```
systemctl list-timers forgejo-dump.timer        # next run
journalctl -u forgejo-dump.service -n 20        # last runs
/srv/forgejo/forgejo-dump.sh                    # dump right now, by hand
```

A failed run leaves no file behind: it writes `.forgejo-dump-*.partial.zip` and renames it only when
the dump succeeds. The service then shows as failed in `systemctl --failed`.

**The dumps live on the same SSD as the live data, so copy them off the box.** From the laptop, over Tailscale:

```
mkdir -p ~/Backups/forgejo
rsync -av --include='forgejo-dump-*.zip' --exclude='*' \
  thai@msi-server.tail2571f1.ts.net:/srv/forgejo/dumps/ ~/Backups/forgejo/
```

This copies only dumps the laptop doesn't have yet, and never the hidden `.partial` files. There's no `--delete`, so the
laptop keeps older dumps after the server's 14-day cleanup removes them. Prune that folder yourself.
The dumps contain your secrets, so keep the copies private.

Not in the dump. Save these once, alongside the dumps:
- `data/ssh/`: the git-over-SSH host keys. Without them a restored server has a new host key and
  clients warn. `sudo tar -C /srv/forgejo/data -czf ~/forgejo-ssh-hostkeys.tgz ssh`
- `compose.yaml` and `forgejo.env`. `forgejo.env` must match the `app.ini` you restore.

## Restore from a dump

Not rehearsed yet. Try it once into a scratch directory before you need it.

```
cd /srv/forgejo
docker compose down                       # stops forgejo + cloudflared, keeps files
mv data data.before-restore               # keep the current state until the restore is verified
mkdir -p data/gitea/conf data/git/repositories restore
unzip -q dumps/forgejo-dump-<timestamp>.zip -d restore/
cp restore/app.ini data/gitea/conf/app.ini
cp -a restore/data/. data/gitea/
[ -d restore/repos ] && cp -a restore/repos/. data/git/repositories/
sqlite3 data/gitea/gitea.db < restore/forgejo-db.sql
sudo cp -a data.before-restore/ssh data/ssh  # or extract forgejo-ssh-hostkeys.tgz
docker compose up -d
docker exec -u git forgejo forgejo admin regenerate hooks --config /data/gitea/conf/app.ini
```

Check the site and a clone, then delete `restore/` and `data.before-restore/`.

## Updates

- **Forgejo 15.x patches:** `./forgejo-dump.sh && docker compose pull forgejo && docker compose up -d forgejo`
  The `15` tag only moves within the LTS line.
- **Next major / LTS:** read the release notes first, dump, then change the image tag in `compose.yaml`.
- **cloudflared:** pinned to `2026.10.1`. Bump the tag in `compose.yaml`, then `docker compose up -d cloudflared`.

## Account recovery (there is no "forgot password" mail)

```
docker exec -u git forgejo forgejo admin user reset-mfa      --config /data/gitea/conf/app.ini --username tyler
docker exec -u git forgejo forgejo admin user change-password --config /data/gitea/conf/app.ini --username tyler --password '<new>'
```

Keep the 2FA recovery code that Forgejo shows when you enable 2FA. These commands need shell access
to this box, so they are the last resort, not the plan.

## Tunnel

- Token: `cloudflared.env`. To rotate it: Cloudflare Zero Trust → Networks → Tunnels → `msi-server-forgejo`
  → refresh token, then write the new one without echoing it:
  `read -rsp 'Tunnel token: ' t && printf 'TUNNEL_TOKEN=%s\n' "$t" > cloudflared.env && unset t && docker compose up -d cloudflared`
- Route: published application `git.tyler-void.dev` → `http://forgejo:3000`. It added one proxied DNS
  record (`git`). The apex (Vercel) and the MX/SPF records (Email Routing) were left untouched.

## Theme

`custom/public/assets/css/theme-enhalation.css` is **generated**. Edit
`theme/templates/forgejo/theme-enhalation.css.in` in btw-arch-dots and run `./scripts/gen-theme.py`,
never this file. It imports Forgejo's own `theme-forgejo-dark.css` and overrides its variables, so a
Forgejo update that adds variables falls back to the dark theme instead of breaking.

- The theme list and the default theme are `FORGEJO__ui__THEMES` / `FORGEJO__ui__DEFAULT_THEME` in `compose.yaml`.
- Your own account keeps the theme you pick under Settings → Appearance.
- After a Forgejo upgrade, open a repo, a diff, an issue with labels and an Actions log once. Those are
  the screens the theme patches beyond plain variables.

## Deploy from the repo

On the laptop, in btw-arch-dots:

```
./scripts/gen-theme.py
rsync -rltv --exclude-from=servers/msi-server/forgejo/.gitignore --exclude=.gitignore \
  servers/msi-server/forgejo/ thai@msi-server.tail2571f1.ts.net:/srv/forgejo/
ssh thai@msi-server.tail2571f1.ts.net 'cd /srv/forgejo && docker compose up -d'
```

Use `-rlt`, never `-a`. `-a` copies the source folder's permissions onto `/srv/forgejo`, which must stay
750. A theme-only change needs no restart: Forgejo serves the file from disk. Reload the page with the
cache bypassed. Changing `compose.yaml` recreates the forgejo container, so the site is down for a few seconds.
