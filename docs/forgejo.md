# Forgejo on msi-server

**The forge at https://git.tyler-void.dev lives in this repo as `servers/msi-server/forgejo/`.**
It is not a `dots.conf` entry: nothing here is laptop config, and `dots` never touches it. You
deploy it to msi-server with `rsync`. The day-to-day runbook (backups, restore, recovery, updates)
ships with the stack as [`servers/msi-server/forgejo/README.md`](../servers/msi-server/forgejo/README.md).
This guide covers how the pieces fit, how to rebuild them from nothing, and the theme pipeline.

## What is running

```
host      msi-server: MSI Modern 14, headless, Wi-Fi only, Tailscale 100.69.193.44
stack     /srv/forgejo (thai:thai 750), compose project "forgejo"
forgejo   codeberg.org/forgejo/forgejo:15 (LTS line), SQLite, data bind-mounted
tunnel    cloudflare/cloudflared, tunnel "msi-server-forgejo", route git.tyler-void.dev → http://forgejo:3000
ssh       100.69.193.44:2222 → the container's sshd. Tailscale only, never the LAN
theme     enhalation (Mocha), generated by scripts/gen-theme.py, the default for visitors
backups   forgejo-dump.timer, 03:30 nightly → /srv/forgejo/dumps, 14 days
```

```
browser ──https──▶ Cloudflare edge ──tunnel (outbound QUIC)──▶ cloudflared ──▶ forgejo:3000
laptop  ──ssh :2222 over Tailscale──────────────────────────────────────────▶ forgejo sshd :22
```

No HTTP port is published on the host. The web is reachable only through the tunnel, and git over
SSH only on the tailnet. Cloudflare's free plan rejects request bodies over about 100 MB, so push
anything large over SSH.

## What is in the repo and what is not

| Tracked here | Only on the server |
|---|---|
| `compose.yaml`, `forgejo-dump.sh`, `systemd/`, `README.md` | `forgejo.env`: SECRET_KEY, INTERNAL_TOKEN, JWT secrets |
| `custom/public/assets/css/theme-enhalation.css` (generated) | `cloudflared.env`: the tunnel token |
| `.gitignore` for everything on the right | `data/` (repos, database, SSH host keys), `dumps/` |

**This repo is public.** The tailnet name, the Tailscale IP and the tunnel ID are committed. None of
them is a credential: the tailnet admits only enrolled devices, and the tunnel needs its token. Never
commit the `.env` files, a dump, or anything from `data/`.

## Deploying a change

```sh
./scripts/gen-theme.py                    # only if a theme template changed
rsync -rltv --exclude-from=servers/msi-server/forgejo/.gitignore --exclude=.gitignore \
  servers/msi-server/forgejo/ thai@msi-server.tail2571f1.ts.net:/srv/forgejo/
ssh thai@msi-server.tail2571f1.ts.net 'cd /srv/forgejo && docker compose up -d'
```

- **`-rlt`, never `-a`** (and never `tar` into `/srv/forgejo`). Both copy the source folder's mode
  onto `/srv/forgejo` and turn 750 into 755. That has already happened once.
- **A theme-only change takes effect without a restart.** Forgejo serves `custom/public` from disk.
  Forgejo sends the CSS as `private, max-age=21600`, so Cloudflare doesn't cache it (`BYPASS`)
  but browsers keep it 6 h. Hard-reload to see a change.
- **A `compose.yaml` change recreates the forgejo container**, so the site is down for a few seconds.
- **The first SSH to the hostname asks about its host key.** Compare it with the fingerprints in the
  stack README.

## The theme

`theme/templates/forgejo/theme-enhalation.css.in` is rendered by the same `scripts/gen-theme.py` as
rofi, swaync and Quickshell, with the same placeholders and contrast gate. On top of the desktop
tokens, the generator exposes `{{font-sans}}`, `{{font-mono}}`, `{{font-display}}` and
`{{font-serif}}` from `tokens.json` `type.families`.

How it works:

1. **It imports `theme-forgejo-dark.css` and overrides variables.** Forgejo's dark theme is one
   `:root` block, and almost every surface points into its `--steel-*` ramp. Remapping that ramp
   onto `ground-deep … ink` themes the page. A variable a future Forgejo adds falls back to the dark
   theme instead of breaking.
2. **The colour families are Catppuccin.** The primary is `accent`. Messages and diffs are the
   `*-soft` tints with `ink` on top. Fields are wells on `ground-sunken` with a `line-strong` edge.
   Metadata grey is `ink-muted`, not a 3:1 grey.
3. **Pastel fills take dark text.** Forgejo puts `--color-white` or inherited light text on coloured
   labels, buttons and badges. That is about 2:1 on Catppuccin pastels, so the template switches
   those rules to `on-accent`. The selector list came from scanning Forgejo 15.0.10's `index.css`
   and `theme-forgejo-dark.css` for every rule that paints an opaque colour-family background.
4. **Fonts are named, not shipped.** Fonts never go in this repo. Visitors with Geist installed get it,
   everyone else the system stack.

### Checking it

- `./scripts/gen-theme.py` must report `contrast gate PASS`. That gate covers the desktop surfaces.
- The web pairings were checked twice when this was built:
  - With `enhalation_ref.contrast()` / `mix_oklab()`: 52 pairings, lowest 3.36 for field edges
    (needs 3) and 4.62 for text (needs 4.5).
  - In a browser, with injected Forgejo markup (labels, buttons, messages in every colour): 30
    elements, lowest 6.31.
- **After any Forgejo major upgrade**, redo the scan in point 3, because new components may paint
  new fills. Fetch the two stylesheets (`/assets/css/index.css`,
  `/assets/css/theme-forgejo-dark.css`) and list rules whose `background` is
  `var(--color-<hue>…)` with no dark `color`. Add any new selector to the template's dark-text block.
  Then look at a repo, a diff, a labelled issue and an Actions log.

## Rebuilding from nothing

On a fresh Arch box with Docker, Tailscale and the user in the `docker` group:

1. **Root setup.**
   ```sh
   sudo install -d -o thai -g thai -m 750 /srv/forgejo
   echo 'net.ipv4.ip_nonlocal_bind = 1' | sudo tee /etc/sysctl.d/91-nonlocal-bind.conf && sudo sysctl --system
   ```
   The sysctl lets Docker bind the Tailscale IP at boot before tailscaled has brought it up.
2. **Deploy this folder** with the rsync above, then create the data folders:
   `install -d -m 750 /srv/forgejo/data; install -d -m 700 /srv/forgejo/dumps`.
3. **Secrets.** Generate them without printing them:
   ```sh
   cd /srv/forgejo && umask 077 && for k in security:SECRET_KEY security:INTERNAL_TOKEN oauth2:JWT_SECRET server:LFS_JWT_SECRET; do
     printf 'FORGEJO__%s__%s=%s\n' "${k%%:*}" "${k#*:}" "$(docker run --rm --entrypoint forgejo codeberg.org/forgejo/forgejo:15 generate secret "${k#*:}")"
   done > forgejo.env
   ```
   Restoring a dump instead? Its `app.ini` already holds secrets, so take `forgejo.env` from the
   old box as well, so the two agree.
4. **Start Forgejo alone and check it is locked** before anything is public:
   ```sh
   docker compose up -d forgejo
   docker exec forgejo wget -S -O- --post-data 'user_name=x&email=x@example.com&password=Xx-12345678&retype=Xx-12345678' http://localhost:3000/user/sign_up 2>&1 | grep HTTP/   # want 403
   docker exec forgejo wget -S -O /dev/null http://localhost:3000/install 2>&1 | grep HTTP/   # want 404
   ```
5. **The tunnel**, in Cloudflare Zero Trust → Networks → Tunnels:
   - Create one, type Cloudflared. On the Docker tab, copy only the token after `--token`; the copy
     button copies the whole `docker run` command.
   - Add the published application route `git` + `tyler-void.dev` → **`http://forgejo:3000`**. The
     URL needs its `http://`; the field has no separate type selector.
   - Write the token without echoing it:
     ```sh
     read -rsp 'Tunnel token: ' t && printf 'TUNNEL_TOKEN=%s\n' "$t" > cloudflared.env && unset t
     docker compose up -d cloudflared
     ```
6. **The admin user.** Run it yourself, so the password only ever appears on your screen:
   ```sh
   docker exec -it -u git forgejo forgejo admin user create --config /data/gitea/conf/app.ini \
     --admin --username tyler --fullname "Tyler" --email <address> \
     --random-password --random-password-length 24 --must-change-password
   ```
   Then log in, set a password, enable 2FA (keep the recovery code), and add an SSH key.
7. **Backups.** Create the repositories folder (`forgejo dump` fails without it), then install the timer:
   ```sh
   docker exec -u git forgejo mkdir -p /data/git/repositories
   sudo install -m 644 /srv/forgejo/systemd/forgejo-dump.{service,timer} /etc/systemd/system/
   sudo systemctl daemon-reload && sudo systemctl enable --now forgejo-dump.timer
   /srv/forgejo/forgejo-dump.sh              # one by hand, now
   ```
8. **Save off the box once:** `data/ssh` (the git host keys, which aren't in any dump) and `forgejo.env`.

## Upload performance: the tunnel is slow inbound (measured 2026-10-24)

The same Contents API upload (`POST /api/v1/repos/<owner>/<repo>/contents`, base64 JSON) was timed
two ways from msi-server: straight to the container, and out through `https://git.tyler-void.dev`
and back in through the tunnel.

| Payload (on the wire) | Direct to Forgejo | Tunnel, QUIC | Tunnel, HTTP/2 |
|---|---|---|---|
| 5 MB (6.7 MB) | 0.6 s | failed (no response, 40 s) | failed (no response, 149 s) |
| 20 MB (26.7 MB) | 1.8 s | 125 s → Cloudflare 524 | 188 s → 524 |
| 50 MB (66.7 MB) | 4.3 s | 113 s | failed (no response, 125 s) |

- **Forgejo is not the bottleneck.** Even at 15 W it processes 50 MB in 4.3 s.
- **The internet line is not the bottleneck either.** Plain HTTPS with Cloudflare does 153 Mbit/s up
  and 215 Mbit/s down. Downloads *out* through the tunnel do ~120 Mbit/s (50 MB in 3.5 s).
- **Uploads *into* the server through the tunnel crawl at ~0.1–1 Mbit/s** on both QUIC and HTTP/2.
  The route from Cloudflare's tunnel edge (SIN, 198.41.x) down to this ISP is the problem, and no
  cloudflared setting fixes a route. There is no public IPv6 here to try another path.
- **Cloudflare also cuts any request off at 100 s** (HTTP 524), whatever Forgejo is doing.

Rules that follow:

- **Big uploads must not go through the tunnel.** Use git over SSH on Tailscale (`:2222`). For HTTP
  API clients, use an endpoint on the tailnet. The laptop reaches msi-server over Tailscale directly on
  the LAN at ~345 Mbit/s.
- **A client on the home network that uses the public URL hairpins.** Its upload goes out to Cloudflare
  in Singapore and back down the same line, through the slow leg.
- **Forgejo has no Git Data write API.** `POST git/blobs` answers 405, `git/trees` and `git/commits`
  404. A GitHub-style blobs → tree → commit uploader can't work. Batch with `POST /contents`
  (`ChangeFiles`, many files in one commit) instead. An existing path needs `operation: update` plus
  its `sha`; `create` on it fails with 422/409.

## Things that bit during the build

- **`forgejo dump` aborts when `/data/git/repositories` doesn't exist**, and Forgejo creates that folder
  only with the first repo. The failed run still left a 0-byte "backup".
- **`forgejo dump --file X` appends `.zip` to a name that doesn't already end in it.** The dump script
  writes `.forgejo-dump-<ts>.partial.zip` and renames it on success, so failures leave nothing that
  looks like a backup.
- **OpenSSH 10.x upgrade on the host:** the running listener launches the new `sshd-session`, so new
  logins can fail until `systemctl restart sshd`. Arch's unit uses `KillMode=process`, so open sessions survive.
- **A `grub` package update** wants `grub-install` as well as `grub-mkconfig`. msi-server also has the
  `--removable` fallback at `EFI/BOOT/BOOTX64.EFI`, because a headless box that loses its NVRAM entry
  is a trip with a monitor.
- **Forgejo's dark theme forces primary labels onto `primary-light-3` with `!important`.** A theme
  that only sets variables can't fix their contrast. The template overrides the rule itself.
